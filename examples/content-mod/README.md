# Content mod example

A Ravel mod that adds content. It declares a block, the item that places it, the
recipe that makes it, the tags that let another mod's recipe find it, its name in
two languages, and the model file Ravel does not generate.

Read [`src/lib.rs`](src/lib.rs) first, and read `ContentMod::declaration` before
anything else. Everything this mod contributes is declared there once:
`Mod::register` claims the registry entries from that declaration and
`ContentMod::generated` produces the pack from the same one, so the block the mod
registers and the block its tag names cannot drift apart.

Three things about it are the point:

- `Cargo.toml` declares one dependency, `ravel-sdk`. That is a mod author's whole
  manifest — same as [`minimal-mod`](../minimal-mod), and
  `tests/conformance/tests/sdk_boundary.rs` reads every example manifest and
  fails if a second entry appears.
- The three kinds of declaration behave differently on purpose. A registry entry
  has one owner, so a second claim on it is a conflict the barrier refuses. A tag
  has none, so this mod and any other mod both contribute to `c:lanterns` and the
  members merge. A resource path has one supplier, so a resource pack loading
  later takes `en_us.json` and the mod it shadowed is named rather than silently
  replaced.
- Generated paths are derived, never spelled. A tag lands at
  `data/<namespace>/tags/<registry>/<path>.json` and a locale at
  `assets/<namespace>/lang/<locale>.json`, and the pack comes out byte for byte
  the same each time it is produced.

`tests/conformance/tests/content_declarations.rs` drives this crate: it claims
its entries through the loader's real registration barrier, provokes a conflict
against a second mod, and compares generated bytes across two declaration orders.

[`package.json`](package.json) and [`provenance.json`](provenance.json) are what
make this crate a package rather than only a crate — the metadata the loader
validates before any of the code above runs. Copy the directory whole into an
instance's `ravel/mods` and `ravel-cli host build` compiles it into that
instance's host. The manifest declares no `resources`, because the model this
mod supplies is a constant in `src/lib.rs` and that field names files the package
ships; only what `source.files` lists is hashed.
`tests/conformance/tests/example_package.rs` recomputes the three things a
hand-written manifest goes stale about: the digests, the file list, and whether
`"id"` still agrees with `#[declare_mod]`. Any edit to a declared file
invalidates the manifest; refresh it with

```console
cargo xtask package digests examples/content-mod
```

which rewrites the digests and nothing else, and says so when there was nothing
to do.
