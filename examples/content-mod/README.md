# Content mod example

A block, item, recipe, convention tags, translations, and supplied assets.
[`ContentMod::declaration`](src/lib.rs) supplies both registration and generated
data, keeping their identifiers aligned.

The example depends only on `ravel-sdk`. Registry entries have one owner;
convention-tag members merge across mods. Tag and locale paths are derived from
their identifiers, and generation is deterministic.

`tests/conformance/tests/integration/content_declarations.rs` checks registration conflicts
and compares generated bytes across declaration orders.

[`package.json`](package.json) and [`provenance.json`](provenance.json) are what
make this crate a package rather than only a crate — the metadata the loader
validates before any of the code above runs. Copy the directory whole into an
instance's `ravel/mods` and `ravel-cli host build` compiles it into that
instance's host. The manifest declares no `resources`, because the model this
mod supplies is a constant in `src/lib.rs` and that field names files the package
ships; only what `source.files` lists is hashed.
`tests/conformance/tests/integration/example_package.rs` recomputes the three things a
hand-written manifest goes stale about: the digests, the file list, and whether
`"id"` still agrees with `#[declare_mod]`. Any edit to a declared file
invalidates the manifest; refresh it with

```console
cargo xtask package digests examples/content-mod
```

which rewrites the digests and nothing else, and says so when there was nothing
to do.
