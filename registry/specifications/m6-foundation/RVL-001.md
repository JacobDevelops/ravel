# RVL-001 — behaviour specification

Wave: `waves/m6-foundation.json`. Method: source-informed reimplementation.
Rights: MIT at the upstream source; see `provenance/m6-foundation/RVL-001.json`.

Confidence markers: **read**, **inferred**, **unknown**.

---

## 1. What this entry is

Makes mob spawners configurable through a typed-stat system: each spawner carries
a set of stats (spawn delay, spawn count, activation range, requires-player,
ignore-spawn-conditions, spawn-rate percentage, and similar), and dedicated items
adjust those stats when applied to a spawner (**read**). The portable core is the
stat value model and how a modifier applies to a stat (**read**).

## 2. The stat value model

Three kinds of stat value (**read**):

- a **percentage** stat: a float clamped to `[-1.0, 1.0]`;
- a **level** stat: an integer;
- a **boolean** stat.

## 3. Applying a modifier

A modifier applies in one of two modes (**read**):

- **add**: add a delta to the current value, then clamp to an optional minimum and
  maximum;
- **set**: overwrite the value.

Applying reports whether the value **actually changed** (**read**). That signal is
load-bearing: the spawner uses it to decide whether to consume the modifier item —
a no-op application must not consume the item (**inferred** — the return is used
as the consume condition).

## 4. What a counterpart implements

The three stat kinds with their clamping, and the add/set application returning a
changed flag.

## 5. What this specification does not specify

- **Block entity, persistence, codecs, tooltips, advancement triggers**: host
  concerns.
- **The full stat catalogue and default values** (**unknown** beyond the kinds in
  §1).
- **Coverage.** Read in full: the stat kinds and the apply modes with the changed
  signal. Everything else: listed, not read.
