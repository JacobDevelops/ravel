## 1. What this entry is

A tiered personal storage drive: a single stored item type per drive, with a very
large per-type capacity, presented across a progression of tiers whose capacity
and slot layout grow with the tier (**read**). The portable core is the tier
progression and its numeric properties; the inventory container, capacity
persistence, and screens are host concerns (**read**).

## 2. The tier progression

Seven tiers in a fixed order, lowest to highest, each with an ordinal starting at
zero (**read**). Each tier carries:

- a **per-slot capacity** that grows with the tier, the top tier being effectively
  unbounded (**read**);
- a display **rarity** that rises across the progression (**read**);
- a **slot layout**: the number of visible rows is the tier ordinal plus one, with
  the top tier fixed at six rows, and the slot count is the row count times nine
  (**read** — the nine-per-row layout is the standard chest-width convention;
  **inferred** that it is chosen for that reason).

The highest tier is a special "creative" tier: unbounded capacity and a fixed row
count rather than one derived from its ordinal (**read**).

## 3. Upgrade support gating

Whether a tier accepts each kind of upgrade — a filter, an energy cell, and a
higher-capacity energy cell — is a function of the tier (**read**). Lower tiers
accept fewer kinds; the gating is monotonic up the progression (**inferred** — the
support flags only ever turn on as the tier rises, never off).

## 4. Progression helpers

- Advancing a tier returns the next tier up, except the top two which stay put
  (**read** — the top tier and the tier below it both return themselves, so
  advancing is idempotent at the ceiling).
- Resolving a tier from an integer ordinal returns the matching tier, defaulting
  to the lowest when the integer is out of range (**read**).

## 5. What a counterpart implements

The tier enum and its pure numeric properties: ordinal, per-slot capacity, rarity,
row and slot counts, per-kind upgrade support, next-tier advance, and
ordinal resolution. All are total functions of the tier with no host state.

## 6. What this specification does not specify

- **The container and its persistence**: the actual stored item, its count, and
  how the large capacity is saved. Host inventory concern.
- **Configuration**: capacities are described here by their in-progression
  relationship; whether any is config-overridable was not determined (**unknown**).
- **Screens and client display**: rarity colour, row rendering. Host client
  concern.
- **Coverage.** Read in full: the tier set and every numeric property quoted in
  §2–§4. Everything else: listed, not read.
