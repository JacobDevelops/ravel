# RVL-089 — behaviour specification

Wave: `waves/m6-foundation.json`. Method: source-informed reimplementation.
Rights: see `provenance/m6-foundation/RVL-089.json`.

Confidence markers: **read**, **inferred**, **unknown**.

---

## 1. What this entry is

A client-only entry that filters which toast notifications appear, by category —
advancement, recipe, system, tutorial — individually or globally (**read**). In
Ravel this maps to an interception at the toast-display point.

## 2. The decision

Given a toast's category and the configuration (per-category blocks plus a global
block), decide whether the toast is suppressed (**read**). A global block
suppresses all; otherwise the per-category flag decides (**inferred** — global
takes precedence over per-category).

## 3. What a counterpart implements

The category enum, the config record (per-category flags plus global), and the
should-block predicate.

## 4. What this specification does not specify

- **Visual customisation** (translucency, positioning, slide animation): client
  render concerns, not behaviour.
- **The interception wiring** to the host toast surface: host concern.
- **Coverage.** Read in full: the categories and the block decision. Visuals:
  named, not specified.
