# RVL-201 — behaviour specification

Wave: `waves/m6-foundation.json` (foundation-method pilot). Method: source-informed
reimplementation. Rights: MIT at the upstream source; see
`provenance/m6-foundation/RVL-201.json` for the pinned artifact and digest.

Confidence markers: **read**, **inferred**, **unknown**.

---

## 1. What this entry is

A large decorative-furniture content mod. The portable, host-independent piece is
one geometry helper: rotating a block's collision box horizontally around the
block centre so a single authored box serves all four horizontal facings
(**read**). Everything else — the block catalogue, models, and screens — is data
and host concern.

## 2. The rotation

The input is an axis-aligned box inside the unit cube `[0,1]³`, given by its
minimum and maximum on each axis, and a horizontal facing (**read**).

Rotation is around the vertical axis through the block centre, i.e. the point
`(0.5, *, 0.5)`. The Y extents are never touched (**read**). For the four
horizontal facings, taking one facing as the identity (the authored orientation),
the other three remap the X and Z extents by quarter turns (**read**):

- the identity facing returns the box unchanged;
- the opposite facing mirrors both X and Z about `0.5`;
- each of the two perpendicular facings swaps the roles of the X and Z extents,
  one of them additionally mirroring, so the box turns a quarter clockwise or
  anticlockwise (**read** — the exact per-facing X/Z remap was read from the
  source's four-way branch and reproduced value for value).

A quarter turn about `0.5` sends a coordinate `c` to `1 - c` on the swapped axis;
the specification requires the arithmetic, not a particular expression of it, and
a counterpart is expected to produce the same four output boxes for the same
inputs.

## 3. What a counterpart implements

The box type over `[0,1]³` and the horizontal-rotation function: identity for the
authored facing, and the three quarter/half-turn remaps for the others, Y left
alone.

## 4. What this specification does not specify

- **Box union and shape optimisation**: combining several rotated boxes into one
  collision shape and simplifying it. Host physics concern.
- **The furniture catalogue**: blocks, models, recipes, tags. Data, not prose
  (restating it here would be the transliteration this process avoids).
- **Which facing is treated as the authored identity** in the host's own
  coordinate convention (**inferred** — the source picks one; a counterpart may
  pick any consistent one so long as the four outputs are consistent with each
  other).
- **Coverage.** Read in full: the rotation branch for all four facings.
  Everything else: listed, not read.
