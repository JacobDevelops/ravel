# RVL-203 — behaviour specification

Wave: `waves/m6-foundation.json` (foundation-method pilot). Method: source-informed
reimplementation. Rights: see `provenance/m6-foundation/RVL-203.json` for the

Confidence markers: **read**, **inferred**, **unknown**.

---

## 1. What this entry is

A decorative content mod adding path blocks — paved, cobbled, and brick surfaces —
that are slightly shorter than a full block, in the manner of the vanilla dirt
path (**read**). It registers blocks and their supporting recipes, tags, and
models; it adds no new mechanic (**read**).

## 2. The one behavioural property

A path block is a full-width block with a reduced height: its collision and
outline top sits below the full cube top, so an entity stands a fraction of a
block lower than on solid ground, exactly as the vanilla path does (**read**).
Beyond that reduced height the blocks behave as ordinary decorative blocks
(**inferred** — no special interaction, redstone, or tick behaviour was found).

## 3. Content is data, not specification

The set of path variants — the surface materials and the base blocks they derive
from — is a catalogue, and the recipes, tags, models, and language entries that
realise it are data (**read**). This document does not write the catalogue out as
prose: reproducing a catalogue in prose is the transliteration failure the
clean-room process exists to prevent. A counterpart carries the catalogue as data
and the reduced-height block behaviour as its only code.

## 4. What a counterpart implements

The path-variant catalogue as data (material × base-block), and the shared reduced-
height block behaviour of §2. Registration into the block and item registries is a
host concern; the counterpart declares the set and the shape.

## 5. What this specification does not specify

- **The exact reduced height** (**unknown** — matches the vanilla path by
  description; the precise fraction was not read from the block definition).
- **The full variant list** (§3): data, listed by shape not enumerated here.
- **Models, textures, recipes, tags, language**: data.
- **Coverage.** Read in part: the block family's reduced-height property and the
  catalogue's shape. The per-variant data was seen as a directory shape, not read
  entry by entry.
