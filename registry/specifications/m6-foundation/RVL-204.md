## 1. What this entry is

Automated world backup with scheduling, compression, incremental/differential
modes, and disk limits (**read**). The portable, host-independent pieces are the
numeric/scheduling helpers (**read**).

## 2. The portable pieces

- **Storage size**: parse a human size string (units of bytes up to larger
  multiples) into a byte count, and pick the largest unit that represents a byte
  count cleanly (**read**).
- **Scheduling**: decide whether a backup is due now, from the schedule config and
  the elapsed time/ticks since the last backup (**read**).
- **Backup chain**: decide whether the next backup must be a full backup rather
  than incremental/differential, from the chain length and config (**read**).
- **Format**: each backup format has a file extension (**read**).

## 3. What a counterpart implements

The storage-unit model with parse and best-unit, the schedule config with the
should-backup-now decision, the should-be-full decision, and the format→extension
map.

## 4. Not specified

The actual archiving, compression codecs, file formats' byte layout, and the
region-locality ordering: host/IO concerns (their structures are named, not
specified). Coverage: read in full — size parsing, scheduling, and chain
decisions.
